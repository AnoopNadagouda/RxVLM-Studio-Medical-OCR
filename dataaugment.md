# RxHandIndia — Complete Dataset Construction Guidelines

**Version:** 1.0  
**Purpose:** Soft guidelines for building a word-level handwritten Indian prescription dataset,
modeled on RxHandBD. No implementation is prescribed — these are architectural decisions,
rationale, and design principles a builder or model can adapt freely.

---

## 1. Project Philosophy

RxHandIndia is not a scraping project. It is a **synthesis pipeline** — it takes
existing raw materials (real prescription images, Indian pharma databases, font assets)
and assembles them into a structured, labeled, reproducible OCR dataset.

Three principles govern every decision:

**Clinical realism first.**
Every grouping, every composite line, every vocabulary entry should reflect how
Indian doctors actually prescribe — not random combinations. A line pairing
Amoxycillin with Clavulanic Acid is realistic. A line pairing Insulin with
Alprazolam is not. The co-occurrence graph enforces this.

**Image coverage drives vocabulary, not the other way around.**
You cannot label what you cannot see. The vocabulary may contain 253,000 entries,
but only drugs with a visual representation (real crop or rendered fallback) may
appear in output images. Dead vocabulary entries enrich grouping logic silently.

**Real beats synthetic, but synthetic beats nothing.**
Prioritise real handwritten crops always. Font rendering is a last resort for
coverage completeness — not a substitute for real data. Tag synthetic entries
so their contribution can be measured and isolated.

## 2. Dataset Anatomy

RxHandIndia mirrors RxHandBD's two-sample-type structure exactly:

### Type A — `single`
A single cropped word image of one drug name.
- One word per image
- Label is the drug name only: `"Augmentin 625"`
- Source: directly from word bank (kalashsh, mehaksingal crops, font renders)
- Difficulty: moderate — one word, one label

### Type B — `rxpage`
A synthetic multi-line prescription image stacking 2–5 drug lines vertically.
- Each line = [dosage form] + [drug name] + optional [modifier]
- Label uses \\n separator: `"tab Augmentin 625\\ncap Dolo 650\\nsyp Aristozyme"`
- Source: generated by composite pipeline from single-word images
- Difficulty: hard — multi-word, multi-line, layout understanding required

The train/val/test split follows 80/10/10. Val and test sets contain only real
handwritten crops, never font-rendered images. Synthetic entries go to train only.

## 3. Vocabulary Architecture

### Layer 1 — Semantic Vocabulary (Full, Text Only)

Source the complete Indian drug database — all 253,000 entries — for use in
grouping and co-occurrence logic. This layer is text only and has no image
requirement. It costs nothing to be comprehensive here.

Fields to retain per entry:
- Brand name (primary label)
- Generic / active ingredient composition
- Dosage form (tablet, capsule, syrup, injection, gel, cream, drops, inhaler)
- ATC therapeutic class (Level 2 preferred)
- Manufacturer

Sources in priority order:

1. **All India Drug Bank** — 253,450 medicines, brand + generic + composition + MRP
   https://www.kaggle.com/datasets/ankushpoddar/all-india-drug-bank-database

2. **A-Z Medicines Dataset of India** — 250K+ entries with pricing
   https://www.kaggle.com/datasets/shudhanshusingh/az-medicine-dataset-of-india

3. **Extensive A-Z Medicines Dataset of India** — 249,398 entries, substitutes + side effects
   https://www.kaggle.com/datasets/riturajsingh2004/extensive-a-z-medicines-dataset-of-india

4. **India Medicines and Drug Info Dataset** — 1mg scrape, name + price + composition
   https://www.kaggle.com/datasets/apkaayush/india-medicines-and-drug-info-dataset

5. **junioralive/Indian-Medicine-Dataset** — 30.3MB CSV, brand + manufacturer + composition
   https://github.com/junioralive/Indian-Medicine-Dataset

### Layer 2 — Visual Vocabulary (Image-Backed Only)

A strict subset of Layer 1. An entry graduates to Layer 2 only when at least
one image can be produced for it — either a real crop or a font render.

Graduation tiers:
- **Tier 1:** Real crop found in word bank for this brand name (preferred)
- **Tier 2:** Real crop found for the generic equivalent (acceptable)
- **Tier 3:** Font rendering succeeds for the brand name (synthetic, train-only)
- **Skip:** None of the above — entry remains Layer 1 only, never appears in images

The visual vocabulary is not fixed — it grows as more real images are collected
or more fonts are added. Build it dynamically at pipeline runtime, not statically.

## 4. Word Image Bank

This is the visual foundation of the dataset — the equivalent of RxHandBD's
5,578 labeled crops. Every image in the bank represents a handwritten instance
of one drug name, standardized to a fixed canvas size.

### Standardization

All images, regardless of source, must be normalized to:
- **Size:** 512 × 128 pixels (width × height) — same as RxHandBD
- **Mode:** RGB
- **Background:** White or near-white
- **Orientation:** Horizontal, word readable left-to-right

### Sources (Priority Order)

**Source 1 — kalashsh/handwritten-medicine-data**
https://www.kaggle.com/datasets/kalashsh/handwritten-medicine-data
The highest-quality source. Pre-cropped word images, one drug per image,
multiple writers per drug (variants labeled -1, -2, -3 etc).
Covers ~474 unique generic drug names. Use as-is after normalization.
These are real handwriting from real writers — maximum authenticity.
Total: ~2,506 images.

**Source 2 — mehaksingal/illegible-medical-prescription-images-dataset**
https://www.kaggle.com/datasets/mehaksingal/illegible-medical-prescription-images-dataset
Full Indian prescription page images from a Pune hospital.
Not labeled at word level — requires two sub-steps:
  - Detection pass: run a word detector to extract bounding boxes
  - Annotation pass: human labeler assigns drug name text to each crop
Estimated yield: 600–900 labeled word crops after annotation.

**Source 3 — chaithanyakota/100-handwritten-medical-records**
https://huggingface.co/datasets/chaithanyakota/100-handwritten-medical-records
100 full Indian prescription records, partially labeled.
Same process as Source 2 (detect → annotate).
Confirms Indian brand names: Montair FX, Nexito, Rejunex CD3.
Estimated yield: 200–300 word crops.

**Source 4 — avi-kai/Medical_Prescription_Handwritten_Words**
https://huggingface.co/datasets/avi-kai/Medical_Prescription_Handwritten_Words
Small collection (~40 images) of labeled medical word images.
Use directly without modification.

**Source 5 — chhavimohitkar/handwritten_medical_prescription_training_dataset**
https://www.kaggle.com/datasets/chhavimohitkar/handwritten_medical_prescription_training_dataset
Additional prescription pages; check for existing labels.
Use same detect → annotate pipeline as Sources 2 and 3.

**Source 6 — Font Rendering (Fallback)**
For any drug in Layer 1 that cannot be sourced from Sources 1–5,
generate a synthetic handwritten image using cursive fonts with
heavy degradation. See Section 7 for rendering guidelines.
These never appear in val or test splits.


### Annotation Protocol (for Sources 2, 3, 5)

When human annotation is required:
- Use Label Studio (https://labelstud.io) with the Indian drug vocabulary
  loaded as an autocomplete taxonomy
- Annotators transcribe exactly what is written, not corrected spelling
- If a word is completely illegible: mark `__illegible__` and exclude
- If a word is a dosage form only (tab, cap) with no drug: exclude
- Target throughput: 100–150 crops per hour with autocomplete assistance

## 5. Drug Grouping Strategy

Grouping determines which drugs appear together on the same rxpage.
Clinically coherent groupings produce realistic composite prescriptions.
Incoherent groupings (random pairing) degrade model learning.

RxHandIndia uses the same 5-strategy cascade as the BD pipeline,
applied in sequence with deduplication across strategies:

### Strategy 1 — ATC Therapeutic Class
Group drugs sharing the same ATC Level-2 category.
Example: All beta-blockers together, all proton pump inhibitors together.
Produces the most clinically coherent groupings.
ATC reference: https://www.whocc.no/atc_ddd_index/

### Strategy 2 — Generic / Active Ingredient
Group drugs sharing the same active ingredient regardless of brand.
Example: Dolo 650, Crocin, Calpol, Paracip → all paracetamol.
Teaches the model that visually different names are semantically equivalent.

### Strategy 3 — Composition Match
Group drugs sharing an active ingredient string from the composition field.
Catches co-formulations: Augmentin (amoxycillin+clavulanate) groups with
standalone Amoxycillin because they share the amoxycillin composition.

### Strategy 4 — Co-occurrence Graph
Group drugs that are frequently co-prescribed in real practice.
Source: co_occurrence_graph.json — already built from 761,919 Indian medicine
documents sourced from the Kaggle and junioralive Indian drug CSVs listed above.
Threshold: conditional probability P(A|B) ≥ 0.30.
Top pairs: aceclofenac+paracetamol (18,867), glimepiride+metformin (13,026),
amoxycillin+clavulanic acid (12,285).

### Strategy 5 — 4-Character Prefix
Group drugs whose names share the same first 4 characters.
Example: Moxi- → Moxikind, Moxiflox, Moxibac, Moxigram.
Deliberately creates visually confusable groups — trains the model to
distinguish between similar-looking drug names.

### Remainder
Any ungrouped drugs after Strategy 5 are chunked into groups of up to
COMPOSITE_MAX_LINES (recommended: 5) arbitrarily.

## 6. Composite Image Construction

### Prescription Line Structure

Each line in an rxpage image is assembled horizontally:

  [dosage_form_image]  [WORD_PAD]  [drug_name_image]  [WORD_PAD]  [modifier_image?]

Dosage form abbreviations used by Indian doctors:
  tab, cap, syp, inj, gel, oint, drop, inh, susp, sachet

Modifier examples: 500mg, BD, OD, TDS, 1-0-1, HS, SOS, × 5 days, PRN

### RxPage Assembly

Multiple lines stacked vertically onto a white canvas:

  [line_1_image]
  [LINE_PAD gap]
  [line_2_image]  ...

Canvas width = widest line. Height = sum of line heights + (N-1) × LINE_PAD.

Recommended constants (match RxHandBD for cross-dataset consistency):
  WORD_PAD            = 12 px
  LINE_PAD            = 16 px
  COMPOSITE_MAX_LINES = 5
  COMPOSITES_PER_GROUP = 4

### Label Format

  Single:  "Augmentin 625"
  RxPage:  "tab Augmentin 625\\ncap Dolo 650\\nsyp Aristozyme"

Use \\n as the only line separator — spaces and commas are not acceptable.

## 7. Font Rendering Guidelines (Synthetic Fallback)

The goal is images that look like rushed ballpoint-pen cursive on a
prescription pad — not clean digital text.

### Recommended Fonts (All Free, Google Fonts OFL License)

Download from https://fonts.google.com :

| Font              | Why Suitable                                        |
|-------------------|-----------------------------------------------------|
| Homemade Apple    | Messy, loopy, highly illegible — most doctor-like   |
| Rock Salt         | Gritty, irregular strokes, rushed pen feel          |
| Ms Madi           | Ultra-cursive, loopy — specialist/surgeon style     |
| Permanent Marker  | Thick marker strokes, pen-on-paper weight           |
| Reenie Beanie     | Tiny, cramped, speed-written appearance             |
| Caveat Bold       | Heavier strokes, natural baseline wobble            |
| Klee One          | Variable stroke width, flowing                      |
| Patrick Hand      | Semi-cursive, round, quick GP writing               |

Use at least 6–8 fonts in rotation. Never use one font exclusively —
the model will learn font features instead of handwriting features.

### Ink and Paper Realism

- Background: slightly off-white (RGB 245–255), never pure white
- Add faint yellowish or grayish tint to simulate aged prescription paper
- Ink colour: near-black with slight blue bias (ballpoint pen)
  Suggested range: R=0–40, G=0–40, B=20–80
- Add subtle brightness variation across the image (uneven ink pressure)

### Geometric Distortion (apply in sequence)

1. **Rotation:** ±15° maximum. Most doctor handwriting tilts slightly.
   Apply to every render.

2. **Horizontal shear:** ±0.25 factor. Simulates cursive forward/backward slant.
   Apply 70% of renders.

3. **Elastic warp:** Low-amplitude, smooth random displacement field.
   Simulates unsteady hand and varying pen pressure across a word.
   Apply 50% of renders. Keep subtle — too much looks unrealistic.

### Degradation (apply after distortion)

4. **Directional smudge (motion blur):** Short kernel 2–6px, random angle.
   Simulates pen smear from fast writing. Apply 50% of renders.

5. **Gaussian noise:** σ = 3–12 range. Paper grain and scan noise.
   Apply to every render.

6. **Gaussian blur:** radius 0.4–1.2. Scan defocus or worn paper.
   Apply 40% of renders.

7. **Paper texture overlay:** Multiply-blend a noise texture.
   Simulates textured prescription pad paper. Apply 40% of renders.

### Caching and Variants

- Cache one canonical render per drug name for reproducibility
- Generate 3–5 additional variants per drug with different random seeds
- Store variants as DrugName_0.png, DrugName_1.png, DrugName_2.png etc.

## 8. Augmentation (Real Images Only)

Real handwritten crops undergo offline augmentation to expand the dataset 3×.
Font-rendered images are NOT augmented — their pipeline already introduces
sufficient variation through randomised rendering parameters.

| Transform          | Range                  | Apply Probability |
|--------------------|------------------------|-------------------|
| Rotation           | ±10°                   | 70%               |
| Brightness/contrast| ±20% each              | 50%               |
| Gaussian blur      | kernel 3–5px           | 40%               |
| Gaussian noise     | variance 10–40         | 40%               |
| Elastic transform  | alpha=1, sigma=10      | 30%               |
| Horizontal flip    | —                      | 0% — NEVER FLIP   |

Never flip horizontally — mirror writing is not in the target domain
and actively harms model learning.

Recommended library: albumentations (https://albumentations.ai)

## 9. Manifest Format

One JSONL file — one JSON object per sample, one line per object.
Format-compatible with RxHandBD manifest for cross-dataset use.

Required fields:
  image     : relative path from dataset root
  text      : ground truth label (\\n-separated for rxpage)
  type      : "single" or "rxpage"
  split     : "train", "val", or "test"
  synthetic : true if font-rendered, false if real handwriting

Recommended optional fields:
  font      : font filename used (synthetic only)
  source    : "kalashsh" | "mehaksingal" | "chaithanyakota" | "avi-kai" | "font"
  writer_id : anonymised writer ID if known (real crops only)

Example entries:
  {"image":"train/word_00042.png","text":"Augmentin 625","type":"single",
   "split":"train","synthetic":false,"source":"kalashsh"}

  {"image":"train/rxpage_00017.png","text":"tab Dolo 650\\ncap Aristozyme",
   "type":"rxpage","split":"train","synthetic":false}

  {"image":"train/word_00891.png","text":"Zithromax 500","type":"single",
   "split":"train","synthetic":true,"font":"HomemadeApple-Regular.ttf",
   "source":"font"}

## 10. Quality Checks

**Vocabulary coverage check**
Count how many of the top-500 most-prescribed Indian drugs have ≥3 real image
samples. Target: ≥80% coverage. Reference top-drug lists:
  - Top 100 Drugs India 2025: https://www.scribd.com/document/923951350/Top-100-Drugs-India-2025
  - CIMS India drug database: https://www.mims.com/india/drug

**Label distribution check**
Plot label character count distribution. Outliers > 40 chars = likely annotation
errors. Outliers < 3 chars = likely dosage form labels without drug names.

**Duplicate detection**
Hash all images. Remove exact duplicates. Near-duplicates from augmentation
are expected within train but must not cross split boundaries.

**Synthetic ratio check**
Target: synthetic images ≤ 40% of train split.
Above 40%, model risks learning font features rather than handwriting.

**Cross-contamination check**
Ensure no drug names from the test split appear in font-rendered training entries.
If "Metformin 500" is a test drug, do not render it for train.
